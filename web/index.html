ALT 휴리스틱이 하는 일

랜드마크 L마다 전처리로 Dijkstra를 두 번 돌려 d(L, v)와 d(v, L)을 모든 v에 대해 저장합니다. 탐색 중에는 삼각 부등식으로 남은 거리 d(v, t)의 하한을 얻습니다.

h(v) = maxL max( d(L,t) − d(L,v),  d(v,L) − d(t,L) )  ≤  d(v,t)

  1. 왜 하한인가. d(L,t) ≤ d(L,v) + d(v,t) 이므로 d(L,t) − d(L,v) ≤ d(v,t). 다른 항도 d(v,L) ≤ d(v,t) + d(t,L)에서 같은 방식으로 나옵니다. 그래서 admissible이고, 같은 논리로 consistent여서 한 번 확정된 노드는 다시 볼 필요가 없습니다.
  2. 언제 정확한가. 랜드마크가 t의 "뒤쪽"에 있어서 v → t 경로가 L → t 최단 경로 위에 놓이면 h(v) = d(v,t)가 됩니다. 그래서 랜드마크는 지도 가장자리에 흩어 놓는 게 좋습니다.
  3. 직선거리 A*와 비교. 직선거리는 도로가 돌아가는 만큼을 모릅니다. ALT는 실제 도로 거리로 만든 하한이라 보통 더 크고, 그만큼 확장 수가 줄어듭니다. 히트맵을 켜고 노드에 마우스를 올리면 두 값을 비교할 수 있습니다.
  4. 비용. 전처리 2k번의 Dijkstra, 메모리 2k·n개의 거리. 질의마다 h(v) 계산은 O(k).

가까운 점끼리는 최적에 가깝고 멀수록 벗어난다는 가설을 랜덤 (출발, 도착) 쌍으로 검증합니다. 기준값은 Dijkstra 최적해입니다.

요약 (Dijkstra 대비)

비용비 = 알고리즘 비용 ÷ 최적 비용 (1.0이 최적). 확장수비 = 확장 노드 ÷ Dijkstra 확장 노드. 속도배 = Dijkstra 시간 ÷ 알고리즘 시간. ρ = 거리와 최적 여부의 스피어만 상관(음수일수록 멀수록 나쁨). BFS는 간선 수가 최소인 경로를 찾으므로 가중치(m) 기준으로는 최적이 아닙니다.

거리 구간별 지표 (구간 = 최적 경로 길이 분위수)
